- **Role in team:** Voice capture & pre-processing pipeline (mic → clean → packetize → send to STT)

## Activity Summary
1. Read and internalized the hackathon challenge statement (bidirectional VI-EN live translation, judging rubric, bonus criteria for on-premise/open models and edge deployment).
2. Designed the Voice-side pipeline scope: capture, DSP cleanup, VAD/turn detection, packetization, handoff to STT — explicitly for a 2-speaker scenario.
3. Authored `docs/audio-streaming-contract.md` (v1.0 → v1.1): a platform-agnostic contract between the Voice module and the STT module, covering:
   - Audio profile (PCM s16le, 16 kHz mono), transport (WSS, binary frames with JSON metadata header).
   - Identifiers: `session_id`, `speaker_id`, `source_id`, `stream_id`, `utterance_id`.
   - Full event lifecycle: `session.start`, `source.register`, `utterance.start`/`end`, `audio.chunk`, `stream.ack`, `stream.resume`, `error`.
   - Two-speaker handling: overlapping speech, short interruptions, filler words ("ừm/ờ/uh/um"), crosstalk between mics.
   - VAD state machine with tunable thresholds (pre-roll, hangover, min speech duration).
   - Noise handling and DSP ordering (AEC → noise suppression → AGC → limiter).
   - Sequence numbering, gap/resend handling, security notes.
   - Mandatory integration test matrix and MVP scope for the 2-day hackathon.
4. **Revision (v1.1)** based on reviewer feedback:
   - Added `heartbeat.ping`/`heartbeat.pong` (§8.7) — runs continuously regardless of VAD/audio state, to detect silent idle-connection drops from proxies/load balancers (typical 30–60s idle timeout) before the next audio chunk would otherwise reveal the failure.
   - Added server-side backpressure (§14.1) — a two-tier signal: soft `stream.throttle` when the STT queue delay crosses a warning threshold, and hard `error(SERVER_BACKPRESSURE)` (with `retry_after_ms`) when it crosses a critical threshold, complementing the existing client-side `stream.degraded`/`stream.gap`.
   - Added §13.1 explaining why `maximum utterance` is capped below Whisper's 30s receptive field (recommended `25–28s`), clarified that STT owns internal chunking for longer inputs, and that Voice's job is only to avoid sending a single utterance past the safe threshold — cross-utterance context stitching belongs to STT/Translation via `continuation_id`.
   - Added corresponding integration tests (idle timeout, sudden disconnect while idle, throttle/backpressure simulation, utterance hitting max duration) and new open decisions for the Voice/STT sync meeting.
